# 見込みボード（第1段階）

「顧客管理・進捗管理 ※社外秘」の `顧客管理` シートを、スマホで見られる月別の見込みボードとして表示するGASのWebアプリです。

## できること
- 列：未振り分け / 空中戦リスト / 今月 / 来月 / 再来月 / 3か月後 / その他（空中戦は未振り分けのすぐ右）
- PC（横幅1100px以上）：未振り分けは上に横長の帯（カードを横に並べ、横スクロール）、その下に空中戦〜その他を画面幅いっぱいに並べて一画面に収める。0件の列は細くたたむ（縦書きの見出しだけ。ドラッグで入れられる）。スマホは今までどおり横スクロール
- カードを長押ししてドラッグすると見込み月を移動できる（詳細画面のボタンでも移動可）
- 複数まとめて移動：月の表示の横の「複数選択」を押してからカードをタップして選び、まとめてドラッグするか、画面下のバーで移動先を選んで「移動」
- 同じ列の中でも長押しして上下にドラッグすると並び替えられる。並び順はシート右端の「並び順」列に保存され、全員の画面と次に開いたときも同じ順になる（まだ並べていない人は最終更新の新しい順で下に並ぶ。成約は上、失客は下に固定）
- 月が変わるとカードは自動で左の列へ移る。見込み月を過ぎたカードは「今月」に残り、赤い「期限切れ」マークが付く
- ◀▶ で表示する月の範囲を先へずらせる
- 担当者の切り替え（開いた人の担当分を最初に表示）と検索
- 詳細画面：進捗ステータスとメモ（C列）の編集、議事録（Googleメモのリンク・PDF・一言メモ）の追加
- 「売買」「インスタ」：担当者ボタンの右に「🏠 売買」「📷 インスタ」（上の大きいタブからは「売買案件」を外した）。押すと全員分をカテゴリーとして、担当別と同じ月の列（未振り分け・今月・来月・再来月…）のボードで見られる。ドラッグで見込み月も動かせる。担当を選んだときのボードには、今までどおりその人の売買・インスタの顧客も出る。ボタンの数字は見込み中の件数
  - 売買：取引種別に「売買」を含む顧客。購入／売却で絞れ、カードに購入・売却の印。上に「年間売買目標（全員）」のゲージ（会社の売買目標＝売上管理表の「売買総合計【◯件】」に対する会社の売買申込件数＝「★売買総申込件数」の行。売買売上・売買単価は「（分析）全体売買売上」の行。担当者の行を足すと飛び込み・HPの売買が二重に入るので会社の行を使う。行が無いときだけ担当者の合計。getSales の saleTargetTotal・companySaleAppMonths・companySaleMonths）。成約・失客は2026年10月からの月の列に出る（それより前の完了した売買案件は出ない）。前の `?view=sale` の URL は「売買」で開く
  - インスタ：紹介種別が「会社集客（インスタ）」か、担当者が「◯◯（インスタ送客）」の人がメイン（KPI はこれだけで数える）。「自己集客（インスタ顧客による紹介／リピート）」の人は点線の薄いカードと「インスタ顧客の紹介／リピート」の印で参考として出し、列の件数・成約の数には入れない（「＋参考◯」と別に出す）。担当が8名以外（例：松井尚史（インスタ送客））の人もインスタの欄にだけ出る（Code.gs の instaKind_）。上にゲージは無く、見込み中・今月の成約・参考の件数だけ
- 担当者：主担当が8名（小嶋・諸本・山田・佐光・澤井・松井拓登・寺田・宮川）の顧客を表示。主担当が8名以外でも「伊藤竣哉（小嶋送客）」のように送客元が8名なら、送客元の画面にだけ表示する。「澤井颯晟（諸本送客）」のように送客元が8名の誰かなら、主担当と送客元の両方の画面に表示する（インスタ送客・神戸アカ・飛び込みは主担当のみ）
- 詳細画面の進捗ボタン：初回電話 → 面談 → 物件提案 → 内覧 → 成約。押すと今日の日付を記録し（K初回電話日・M面談日・新しく作る「物件提案日」列・N内覧日・成約はQ申込日）、B列のステータスを自動で書き換える（成約はシートの書式に合わせて「完了」と入れる）。内覧は「＋1回」でO列の内覧回数が増える（N列は1回目の日付のまま）。押し間違いは同じボタンをもう一度押すと取り消し。1回ごとに「進捗ログ」シートへ記録
- 成約・失客の表示：進捗ボタンの「成約」を押すと、B列が「完了」になり、その顧客は今月の列に移って金色に光るカードになり、列も金色になって「🏆 成約 ◯件」が出る。「失客」はグレーアウトして列の下に残る。成約の判定は「B列が完了」だけ（B列が完了でないのに申込日が入っている人は、アプリを使う前の過去の案件として、ボードには出さない）。成約は申込日の月の列に金色で出る（申込日が今月より先の日付なら見込み月の列。「11/5」のように年なしで打つと翌年の日付になることがあるため）。出すのは2026年10月〜今月だけ（Code.gs の BOARD_FROM）。失客は見込み月の列に出る（アプリで「今月の失客」を押した人だけ）。どちらもその月の列に記録として残り、◀ で過去の月にさかのぼると「この月に誰が決まって誰が失客したか」が見られる（最大24か月前まで）。成約・失客のカードはドラッグで動かせない
- ×（ボードから外す）：カードの右上の × で、そのカードをボードから外せる（確認あり）。シートの見込み月が「非表示:元の値」（例：非表示:2026-11）になるだけで、B列などほかの列は触らない。外した人は月の表示の横の「外した人 ◯」から一覧で見られ、「戻す」で外す前の列に戻る
- 予定：初回電話・面談・内覧（来社）は、ボタンを押すと「実施した」か「予定を入れる」を選べる。日付（「10/25」などの手入力、📅 のカレンダー、今日・明日・明後日のボタン）、開始時間（「14:00」「1430」などの手入力か、8:00〜22:30 の30分刻みのプルダウン）、所要時間（30分単位。初期値は電話30分・面談1時間・内覧5時間）を選ぶ。予定は右端の「初回電話予定」「面談予定」「内覧予定」列に「2026-10-25 14:00〜15:30」の形で入り、担当者のGoogleカレンダーにも所要時間分の予定として入る（件名は「【面談】顧客名」）（変更・取り消しでカレンダーも動く）。予定は分析に数えず、「実施した」を押したときに実施として記録する（予定の日が過ぎていれば予定の日付で記録）。予定の日時を過ぎても実施していないと、カードに「実施報告待ち」と赤く出る
- 予定を入れるカレンダー：担当者のカレンダー（STAFF の email）。小嶋さん・諸本さんは info@ のふだんのカレンダーが全員に共有されているので、info@ の中のそれぞれの専用カレンダー「小嶋勇輝」「諸本雅広」（STAFF の calendar。契約進捗は KeiyakuCode.gs の STAFF_CALENDARS）に入れる。追客アラートのメールは今までどおり info@ に届く。担当を小嶋→諸本のように変えたときも、入れる先のカレンダーが違えば先の予定を移す
- カレンダーの色：アプリが入れる予定（初回電話・面談・内覧の予定、追客アラート、契約進捗の鍵渡し）は担当の色にする。Googleカレンダーの予定の色は決まった11色だけなので、担当カラーにいちばん近い色（小嶋＝ミカン、諸本＝ピーコック、山田＝フラミンゴ、澤井＝ブドウ、松井＝バナナ、寺田＝グラファイト、宮川＝トマト。Code.gs の STAFF の event、KeiyakuCode.gs の STAFF_EVENT_COLORS）。佐光さんのベージュは11色に無いので予定には色を付けず、カレンダー全体の色（カスタムでベージュ #ebdfc2）で出す。招待で入った予定は、担当者側ではその人のカレンダーの色で出る
- 名前の修正：詳細画面の「名前を直す」で名前とフリガナを直せる。シートのA列が「名前（フリガナ）」に変わり、議事録フォルダとカレンダーの予定の件名も新しい名前になる
- 担当の変更：詳細画面の「担当（シートのE列）」で、上の段で主担当（8名）、下の段でその人の送客の付け方（送客なし／小嶋送客／諸本送客／インスタ送客／飛び込み など）を押すと、確認のうえシートのE列に書き込む。選択肢はE列のプルダウン（入力規則の範囲＝「※触らない紹介件数」シートR48:R119）をそのまま読む（Code.gs の staffOptions_。その顧客の行のプルダウン、無ければ一番下の行から上へ探す。2行目にはプルダウンが無いため。プルダウンにない組み合わせは出ない）。小嶋さんから澤井さんへ引き継ぐときなどは「小嶋送客」に「おすすめ」が付く。進捗ログに「担当変更（前 → 後）」を残し、契約進捗につながっている案件は契約進捗の担当も新しい主担当に変える（setStaff）。通知先（主担当。主担当が8名以外なら送客元）が変わったときは、すでに入っている先の予定（初回電話・面談・内覧の予定と、今日以降の追客アラート）を前の担当のカレンダーから消して、新しい担当のカレンダーに同じ日時で作り直す（moveEventsToOwner_。過ぎた予定はそのまま）。担当を変えたあとに入れる予定・追客メールは、もともとその時のE列を見るので新しい担当に行く
- 取引種別：詳細画面の「賃貸／売買（購入）／売買（売却）」ボタンで変えられる。シートのD列に反映する
- 段階以外の状態ボタン：追客・時期待ち・返答待ち（B列だけ書き換え）。プルダウンは廃止
- 「成績ダッシュボード」タブ：押すと同じタブのまま成績ダッシュボード（分析ボード）に切り替わる（前回見ていた分析ページが開く）。分析ボードの上にも「見込みボード」「売買案件」「成績ダッシュボード」の同じタブがあり、押すと見込みボードに戻る（URL の `?view=sale` で売買案件が開く）。読み込みは別なので見込みボードは重くならない
- 契約進捗アプリとの連携：見込みボードで「成約」を押すと（賃貸のみ）、契約進捗DB（Code.gs の CONTRACT_DB_ID）の「案件」シートに案件を作り、案件IDを顧客管理のアプリ用の列の最後「契約進捗ID」に入れる（同じ担当〔主担当か送客元。先頭2文字〕・同じ名前〔空白・様・さん・カッコ内を除く〕の案件があればそれにつなぐ）。見込みボードで名前を直すと、契約進捗の案件のお客様名も同じに直す。成約カードに「📝 契約 12/40・審査承認時」「◯日動きなし」「完了ボタン待ち」「契約完了」を出し、契約進捗が「完了」になった成約カードは、金色から担当の色（STAFF の色）の金ピカのグラデーションに変わり、リボンが「契約完了」になる。詳細の「契約進捗」欄に「契約進捗を開く」ボタン。進み具合はボードを出したあとに別で読む（getContractProgress、5分キャッシュ＋端末に前回分）。すでに成約の人は詳細を開いたときに探してつなぎ、見つからなければ「契約進捗を作る」ボタンと、同じ担当でまだどの顧客ともつながっていない案件の一覧（名前が近い順。押すとつなぐ。名前の書き方が違うとき用）。成約を取り消しても案件は消さない。売上表にお客様名を入れたときは、契約進捗アプリ側（KeiyakuCode.gs＝契約進捗の Code.gs。scanTab_ から linkBoardDeal_ を呼ぶ）で同じ案件につなぐ。上のタブの「契約進捗 ↗」（見込みボード・成績ダッシュボードとも）は、契約進捗アプリの一覧（担当を選ぶ画面）を別のタブで開くリンクだけ。左上の🏠はホーム画面（このアプリの URL に ?page=home。Code.gs の homePage_。見込みボード・成績ダッシュボード・契約進捗・マニュアル・営業資料を大きいカードで並べるだけの入口。カードは homeApps_ に足す。スマホのホーム画面への置き方の説明つき）へ戻るリンク。その右の「📖 マニュアル」は新人用マニュアルのアプリ（Code.gs の MANUAL_APP_URL。空ならタブを出さない）を別のタブで開くリンクだけ（スマホ幅では📖だけ）。CONTRACT_DB_ID が空なら連携はすべて出ない
- 契約進捗アプリの画面（App.html。最新は「契約進捗 コードのコピー」のページ https://claude.ai/artifact/QFduRvP9CbStGiBiq2L2CN にある。KeiyakuCode.gs と同じ中身の Code.gs もそこにある）
  - 案件の画面：「次はこれ！」を小さくし、その上にすぐ書けるメモ欄（保存すると「面談・メモ」と同じメモシートに入り、48時間のカウントもリセット）と、いちばん新しいメモを表示。書きかけのメモはチェックを押しても消えない
  - 案件一覧のカードに、いちばん新しいメモを1行で表示（apiList の memo）
  - チェックは「押すと ✓、もう一度押すと外れる」だけ（✕〔該当なし〕にはならない。前に ✕ にしたものは押すと外れる）。段階ごとの「残りを全部✓」「リセット」はそのまま
  - 鍵渡しの予定：入居日が入っていると「🔓 鍵渡しをカレンダーに入れる」ボタン。押すと入居日の前日 17:00〜20:00 と当日 10:00〜12:00 に「〇〇様🔓鍵渡し」を担当者のカレンダーに入れる（KeiyakuCode.gs の apiKeyEvents・KEY_SLOTS）。担当者のメールは契約進捗DBの「メンバー」シート、無ければ STAFF_EMAILS（見込みボードの STAFF と同じ）。担当者が持ち主（小嶋さん）に「予定の変更」権限でカレンダーを共有していれば直接入り、していなければ持ち主のカレンダーに作って担当者を招待。入れた予定は「引き継ぎ」シートのキー keyEvents に残り、入居日が変わったら「入れ直す」で前の予定を消して作り直す。エディタで checkCalendars を実行すると、担当者ごとに直接書き込めるかが実行ログに出る
- シートを直接直したとき：setup で入る「シートの編集」トリガー（onSheetEdit）が、アプリがためている顧客の一覧（2分キャッシュ）をすぐ捨てるので、次に開いたとき・↻ でシートの値が出る。↻ は必ずシートから読み直す（getBoard(true)）
- 成約の速さ：「成約」を押したら、シートへの保存を待たずに先に今月の列へ移して光らせる（winCase。保存に失敗したら元に戻す）。サーバー側は行を1回だけ読んで変わったセルだけ書き、追客アラートの解除も同じ処理の中でする（recordStage_）。契約進捗の案件づくりは保存のあとに裏で呼ぶ（contractAfterWin）
- 保存の順番待ち（ロック）：同時に同じ行を書き換えて壊さないよう、保存は順番待ちする（最大30秒＝LOCK_WAIT。待ちきれないと「ロックのタイムアウト」）。契約進捗DBを読んで探す間は順番待ちをふさがず、案件を新しく作る一瞬だけ順番待ちする（ensureContract_）。複数選択の移動は1回の保存でまとめて書く（moveCustomers）
- キャッシュ：顧客の一覧は10分ためる（CACHE_TTL。アプリから書いたとき・シートを直接直したときは捨てる）。setup で入る1分ごとのトリガー（warmBoardCache）が、捨てられた一覧をすぐ作り直しておくので、書き込みのあとに最初に開く人も待たされない。売上管理表は30分ためる
- 速さの工夫：⑤成績ダッシュボードのグラフは画面に入る少し前に描く（lazyChart。下の方のグラフを開いた瞬間に全部描かない）。⑥成績ダッシュボードは今のページを出したあと手が空いたときに、ほかのページのデータと見込みボードのデータ（mikomi.cache.v1.board / sales）を裏で読んでおく（prefetchRest）。⑦見込みボードは、成績ダッシュボードを使ったことのある人なら、ボードを出したあと前回見ていたページのデータを裏で読んでおく（prefetchAnalysis。10分に1回まで）。①成績ダッシュボードのページのタブは、アプリを開き直さずにその場で切り替える（データは1回読んだら使い回す。URL も google.script.history で今のページに合わせる）。②見込みボード・成績ダッシュボードとも、前回読んだ数字をこの端末（localStorage。キーは mikomi.cache.v1.* と nenji.cache.v1.*）に覚えておき、開いた瞬間に表示。裏で最新を読み、変わっていれば描き直す（右上に「前回の数字を表示中・最新を確認しています…」）。見込みボードはカードの詳細を開いている間や複数選択中は描き直さない

## セットアップ（PCで約10分）
1. https://script.google.com で「新しいプロジェクト」を作り、名前を「見込みボード」にする
2. `コード.gs` の中身を `Code.gs` の内容に置き換える
3. ＋ → HTML で `Index` というファイルを作り、`Index.html` の内容を貼り付ける
4. プロジェクトの設定 → 「appsscript.json をエディタで表示」にチェックを入れ、`appsscript.json` の内容に置き換える
5. `Code.gs` の `STAFF` に、7名の会社アカウントのメールアドレスを入れる
6. 上部の関数選択で `setup` を選んで「実行」→ 権限を許可する（ここで列とシートが作られます）
7. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**（会社のドメイン）内の全員**
8. 発行されたURLを8名に共有する。スマホではURLを開き、「ホーム画面に追加」でアプリのように使えます

コードを変更したときは「デプロイを管理」→ 編集 → バージョン「新バージョン」で更新します（URLは変わりません）。

- 営業資料（?page=docs。Code.gs の getSalesDocs / docsPage_）：共有ドライブの「営業資料（アプリ用）」フォルダ（SALES_DOCS_FOLDER_ID）を読んで、中のフォルダをカテゴリ（上のボタン）、ファイルをカードで出す。資料を増やすときはドライブのフォルダに入れるだけ（10分キャッシュ、↻で読み直し）。フォルダ名・ファイル名の頭の番号（01_ など）は並び順に使って画面では消す。ファイル名の頭に★でそのカテゴリの一番上（おすすめ）。ドライブの「説明」がカードの説明。ショートカットも置ける（元のファイルを開く）。カテゴリの中のフォルダは1段まで読む。14日以内に更新したものに NEW。名前の「※社外秘」は消して🔒の印、名前に「触らない」があるもの・頭が「_」のものは出さない。一番上のフォルダに直接置いたファイルは「ツール・その他」。検索はファイル名・説明・フォルダ名。アプリはデプロイした人の権限でフォルダを読むので、開く人がそのファイルを見られる権限は別に要る
